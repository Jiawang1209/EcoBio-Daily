# Goal 2 — 把 LLM 评分接进 pipeline

Part of the P1 LLM-integration goal series (G1 → G5). Depends on G1
(`src/ecobio_daily/llm_scoring.py`) being merged. After this goal LLM
relevance scoring is live in the daily pipeline; report prose still uses
RSS summaries (G4/G5 will replace those).

---

## 一句话目标

在 `src/ecobio_daily/pipeline.py` 里，已通过关键词打分的候选条目，
按相关性降序取前 N 条调 LLM 评分，过滤掉 LLM 评分 < 6 的，
LLM 不可用时（无 key / 抛错）走原有关键词排序，不阻断管线。

## 已有基础（直接用）

- `src/ecobio_daily/llm_scoring.py`：`score_relevance(item, client)`、`batch_score(items, client)`（G1 已完成）
- `src/ecobio_daily/llm.py`：`LLMClient` + `load_dotenv`
- `src/ecobio_daily/config.py`：`load_llm_config()`、`LLMConfig`
- 当前 pipeline 流程：fetch → dedupe → `score_item`（关键词）→ filter by `min_relevance_score`
- `config/llm.yaml` 已有 `llm.enabled`、`budget.max_items_per_run=12`
- `.env` 里 `CSTCLOUD_API_KEY` 已就绪

## 范围

**DO:**

- 在 `pipeline.py` 现有打分流程之后插入 LLM 评分层：
  - 只对通过关键词阈值的 top N 条评分（N 取 `llm.budget.max_items_per_run`）
  - LLM 分数挂到 `ScoredItem` 上（新加字段 `llm_score: int | None`，默认 `None`）
  - 过滤：LLM 分 `>= 6` 的留下；LLM 失败的整批走 fallback（保留关键词排序）
- `src/ecobio_daily/models.py`：`ScoredItem` 加 `llm_score: int | None = None`
- 用 dependency injection：pipeline 接受 `llm_client: LLMClient | None` 参数，`None` 时跳过 LLM
- `tests/test_pipeline.py` 增加：
  - 注入 mock client 模拟高/低分场景
  - 注入 `None` 时跳过 LLM、行为不变
  - LLM 全部失败时管线不挂、走 fallback

**DON'T:**

- 不实现缓存（G3）
- 不改打分阈值的默认值
- 不动 `render.py` / `digest.py`
- 不动 `llm_scoring.py` 的实现细节
