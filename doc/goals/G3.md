# Goal 3 — LLM 响应缓存

Part of the P1 LLM-integration goal series (G1 → G5). Depends on G2
being merged (LLM scoring wired into pipeline). After this goal,
re-running `scripts/run_daily.py` on a day that has already been
scored is effectively free in tokens — important for the prompt
iteration in G4 / G5.

---

## 一句话目标

给 `LLMClient.chat()` 加内容寻址的本地 JSON 缓存：
启用后，同样的 `(model, messages, response_format, temperature)` 命中缓存直接返回，
不再调网关。

## 已有基础（直接用）

- `src/ecobio_daily/llm.py`：`LLMClient(config, http_client=None, env=None)`、
  `LLMClient.chat(messages, profile=None, task=None, response_format=None)`
- `config/llm.yaml` 已有：
  ```yaml
  budget:
    max_items_per_run: 12
    cache_llm_outputs: true
    cache_dir: data/cache/llm
  ```
  `LLMConfig` 当前**不**解析 `budget` 段（Pydantic 默认忽略未知字段）
- `data/cache/` 已在 `.gitignore` 里，缓存文件不会被提交
- `src/ecobio_daily/llm_scoring.py` 和 `pipeline.py` 都通过 `client.chat(...)` 调网关，
  所以缓存只要写在 `LLMClient.chat()` 里就同时覆盖评分和未来的简报生成

## 范围

**DO:**

- 新建 `src/ecobio_daily/llm_cache.py`：
  - `cache_key(model: str, messages: list[dict], response_format: str | None, temperature: float) -> str`
    返回 `sha256` 十六进制
  - `read_cache(cache_dir: Path, key: str) -> str | None`
  - `write_cache(cache_dir: Path, key: str, value: str, model: str) -> None`
    缓存文件名：`<sha256>.json`，内容
    `{"value": "<响应文本>", "model": "...", "created_at": "<isoformat>"}`
- 改 `src/ecobio_daily/llm.py`：
  - `LLMClient.__init__` 新增 `cache_dir: Path | None = None`
  - `LLMClient.chat()` 当 `cache_dir is not None`：
    1. 算 key
    2. 命中缓存：直接返回字符串
    3. miss：调网关，**成功后**写盘再返回（4xx/5xx 不写缓存）
- 改 `src/ecobio_daily/config.py`：
  - 加 `LLMBudget(BaseModel)`：字段 `max_items_per_run: int = 12`、
    `cache_llm_outputs: bool = False`、`cache_dir: str = "data/cache/llm"`
  - `LLMConfig` 加字段 `budget: LLMBudget = Field(default_factory=LLMBudget)`
- 改 `scripts/run_daily.py`：
  - `_maybe_build_llm_client` 在 `llm_config.budget.cache_llm_outputs` 为 true 时，
    把 `Path(llm_config.budget.cache_dir)` 传给 `LLMClient(cache_dir=...)`
- 新建 `tests/test_llm_cache.py`：
  - 纯函数 `cache_key` 测试：
    - 改 `model` 缓存 key 变化
    - 改 `messages` 内容 key 变化
    - 改 `response_format` key 变化
    - 改 `temperature` key 变化
  - `read_cache` 文件不存在返回 `None`
  - `write_cache` + `read_cache` 往返
- 改 `tests/test_llm.py`：
  - 新增 4 个集成测试（用 `httpx.MockTransport` 数 request 次数）：
    - 同一 messages 调两次只发 1 次 HTTP（cache hit）
    - 改 temperature 缓存失效（发 2 次 HTTP）
    - `cache_dir=None` 时不读不写
    - HTTP 5xx 不写缓存（下一次还会调网关）

**DON'T:**

- 不做 TTL（科研日报每天新内容，没必要）
- 不做缓存大小上限
- 不动 `llm_scoring.py` / `pipeline.py` 的接口
- 不加新依赖（`hashlib` + `json` + `datetime` 都是 stdlib）
- 不重命名已有字段
