# Goal 4 — 中文研究简报生成函数

Part of the P1 LLM-integration goal series (G1 → G5). Depends on G3.
After this goal there's a pure function that turns a list of `ScoredItem`
into a structured Chinese research brief; **rendering is still G5's job**.

---

## 一句话目标

在 `src/ecobio_daily/llm_digest.py` 实现
`generate_section(topic_name, items, client) -> dict | None`，
对一个主题下的候选条目，让 `deepseek-v3.2` 写一段结构化中文研究简报，
任何失败（API / 解析）都返回 `None`，不 raise。

## 已有基础（直接用）

- `LLMClient.chat(messages, task="digest_generation", response_format="json_object")`
  自动走 `deepseek-v3.2`（routing 已配好）
- 缓存已生效（G3）：写同样 prompt 不重花 token
- `config/llm.yaml.digest_zh` 已有完整 schema 定义：
  ```yaml
  output_schema:
    highlight_count: 3
    item_fields: [title, summary_zh, why_it_matters, evidence_type, caveat, source_url]
  writing_rules:
    - 不夸大相关性，不把相关性写成因果。
    - 区分实验发现、模型推断、综述观点和媒体报道。
    - 保留关键研究对象、尺度、方法和限制。
    - 中文表达要凝练，不逐句翻译英文摘要。
    - 不生成无来源支撑的医学、农业或政策建议。
  ```
- `src/ecobio_daily/models.py`：`ScoredItem` 包含 `item: SourceItem` + `relevance_score` + `topic_scores` + `llm_score`
- 项目 scope（直接抄进 prompt）：森林/农田/草地土壤微生物 + 微生物驱动 BGC

## 范围

**DO:**

- 新建 `templates/prompts/digest_section_zh.md.j2`：
  - 系统消息：写明 scope + 上面的 5 条 `writing_rules`（固化到 prompt 里）
  - 用户消息：注入主题名 + 每条 item 的 `title` / `summary` / `authors` / `source` / `url`
  - 要求严格 JSON 输出：
    ```
    {
      "section_title": "<中文小节标题>",
      "highlights": ["<3 条要点 ≤ 30 字>", "...", "..."],
      "items": [
        {
          "title": "<原标题，原样保留>",
          "summary_zh": "<2-3 句中文凝练>",
          "why_it_matters": "<1 句中文>",
          "evidence_type": "实验|模型|综述|观点",
          "caveat": "<1 句限制；没就 null>",
          "source_url": "<原 url>"
        }
      ]
    }
    ```
- 新建 `src/ecobio_daily/llm_digest.py`：
  - `generate_section(topic_name: str, items: list[ScoredItem], client: LLMClient) -> dict | None`
    - 用 `response_format="json_object"` + `client.chat(task="digest_generation")`
    - `json.loads` 解析失败 → `None`
    - LLM 调用失败（`LLMError`）→ `None`
    - 不做字段补全 / 不做 schema 校验（让渲染层兜底）
- 新建 `tests/test_llm_digest.py`：
  - mock 一个高质量 JSON 响应，验证字段齐全
  - mock 一个坏 JSON（不可解析），验证返回 `None`
  - mock HTTP 500（`LLMRequestError`），验证返回 `None`
  - 验证 prompt 里包含所有 item 的 title（注入正确）
  - 验证 prompt 里包含 topic_name

**DON'T:**

- 不接 `render.py` / `digest.py`（G5 才做）
- 不做"高亮挑选"逻辑（让 LLM 直接出 `highlights`）
- 不动 `pipeline.py`
- 不加新依赖
- 不在 .py 里硬塞 prompt——所有 prompt 文本必须在 `.j2` 模板里
