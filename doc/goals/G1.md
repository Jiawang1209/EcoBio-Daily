# Goal 1 — LLM 相关性评分函数

Part of the P1 LLM-integration goal series (G1 → G5). This goal is self-contained:
finishing it lands a committable, working scoring module without touching the pipeline.

---

## 一句话目标

在 `src/ecobio_daily/llm_scoring.py` 实现 `score_relevance(item, client) -> int`，
用 CSTCloud uni-api 的 `deepseek-v4-flash` 给每条 `SourceItem` 打 0-10 分。

## 已有基础（直接用）

- `src/ecobio_daily/llm.py`：`LLMClient` 已就绪，`task="relevance_scoring"` 自动路由到 flash
- `src/ecobio_daily/models.py`：`SourceItem(title, summary, authors, tags, ...)`
- 项目 scope：森林/农田/草地土壤微生物 + 微生物驱动生物地球化学。
  排除：宿主关联微生物组、临床、水/气、广义生态。详见 `doc/current-work-tasks.md`
- `config/llm.yaml` routing 已配好，`.env` 里 `CSTCLOUD_API_KEY` 已就绪

## 范围

**DO:**

- 新建 `templates/prompts/relevance_score.md.j2`（jinja2，已在依赖）
  - prompt 写死 scope（森林/农田/草地土壤 + bgc）和排除项（gut/clinical/marine/atmosphere）
  - 要求 LLM 返回严格 JSON：`{"score": 0-10, "reason": "<=20 字中文"}`
- `src/ecobio_daily/llm_scoring.py` 实现：
  - `score_relevance(item: SourceItem, client: LLMClient) -> int`
  - `batch_score(items: list[SourceItem], client: LLMClient) -> list[int]`
  - 用 `response_format="json_object"`
  - JSON 解析失败 → 返回 `-1`（不要 raise）
  - LLM 调用失败 → 返回 `-1`（不要 raise）
- `tests/test_llm_scoring.py` 用 `httpx.MockTransport`：
  - 高分土壤论文
  - 低分临床论文
  - JSON 解析失败 fallback
  - HTTP 错误 fallback

**DON'T:**

- 不改 `pipeline.py`（下一个 goal 才做）
- 不做缓存（G3 才做）
- 不做并发（顺序就够）
- 不加新依赖
- 不顺手改其他代码
