# Goal 11 — 管线可观测性（D1 / P2c 第一项）

Right now the only signal a run produces is two stderr lines:
`LLM brief: …` and `LLM grounding: …`. If the digest quality drifts
in 4 weeks (say, fetch silently drops, or LLM scoring becomes too
aggressive), there's no audit trail to localize the failure.

This goal adds a structured per-run metrics file that records the
funnel at every stage so quality drift becomes diagnosable.

---

## 一句话目标

每次跑日报，把每个 pipeline 阶段的 `(in_count, out_count, [extras])` 写到
`data/runs/<date>.json`，让 fetch / dedup / score / LLM brief / grounding
各阶段的"漏斗"全部可查。

## 已有基础

- `src/ecobio_daily/pipeline.py::run_pipeline_from_items` 是单一入口，所有阶段都在它里面
- `data/` 已有 raw / processed / cache / state 子目录，新加 `data/runs/`
- `.gitignore` 已经用 `data/<dir>/*` + `!.gitkeep` 的模式
- 已有 `_attach_llm_briefs` 内部维护 ok/failed/grounded/ungrounded 计数

## 范围

**DO:**

- 新建 `src/ecobio_daily/run_metrics.py`：
  - `class RunMetrics`：dataclass / plain dict with helpers
    - 字段：`date`, `started_at`, `completed_at`, `duration_seconds`, `stages: dict[str, Any]`
    - 方法：`record(stage_name, **kwargs)` 写到 `stages` 下
    - 方法：`save(path: Path)` 写 JSON（`ensure_ascii=False, indent=2`）
- 改 `src/ecobio_daily/pipeline.py`：
  - `run_pipeline_from_items` 加一个 `metrics: RunMetrics | None = None` 参数（默认 None 不破坏 API）
  - 在 metrics 非 None 时每个阶段后记一条：
    - `fetch_total`：`{ in: 全部抓到的, sources: [{id, count, error?}] }`（注意 fetch 在 run_pipeline 外层做，需要那一层也接入）
    - `date_window`: `{ in, out }`
    - `url_dedup`: `{ in, out }`
    - `intra_day_doi_dedup`: `{ in, out }`
    - `cross_day_doi_dedup`: `{ in, out, prior_seen_count }`
    - `keyword_score`: `{ in, above_threshold }`（above_threshold = passing `min_relevance_score`）
    - `llm_relevance`: `{ candidates: int, kept: int, fallback_used: bool }`（fallback_used = 所有 -1 时整批保留）
    - `build_digest`: `{ sections: int, items: int, highlights: int }`
    - `llm_brief`: `{ ok: int, failed: int }`
    - `llm_grounding`: `{ passed: int, failed: int, errored: int }`（errored = check_groundedness 返回 None）
    - `output`: `{ zh: str, en: str | null }`
  - `_apply_llm_scoring` 和 `_attach_llm_briefs` 各加 `metrics: RunMetrics | None = None` 参数（不强制）
- 改 `src/ecobio_daily/pipeline.py::run_pipeline`（外层）：
  - 也接 metrics 参数；fetch 循环里记每个 source 的 count / error
- 改 `scripts/run_daily.py`：
  - 总是创建一个 RunMetrics，传给 `run_pipeline`
  - 结束时 `metrics.save(output_root / "data" / "runs" / f"{digest_date}.json")`
- `.gitignore` 加 `data/runs/*` + `!data/runs/.gitkeep`
- 新建 `data/runs/.gitkeep`
- 测试：
  - `tests/test_run_metrics.py`：record + save 往返
  - `tests/test_pipeline.py` 加一条：传入 metrics → run → 检查 stages 包含 url_dedup / intra_day_doi_dedup / cross_day_doi_dedup / keyword_score 这些 key

**DON'T:**

- 不改 stderr 打印行为（保留作为快速反馈）
- 不加 token / cost 统计（下一个 micro-iteration）
- 不动 schema 之外的现有数据落盘格式
- 不引入 logging 库（写 JSON 比配 logger 简单）
- 不加新依赖
