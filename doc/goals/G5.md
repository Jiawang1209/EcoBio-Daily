# Goal 5 — 把中文简报接进渲染 + 跑一次真实日报

Final goal in the P1 LLM-integration series. Depends on G4
(`generate_section`). After this goal the daily Markdown digest
shows LLM-written Chinese prose per topic; any per-topic LLM failure
falls back to the legacy RSS-summary block for that topic only, never
the whole digest.

This goal is **interactive** — prompt may need 1-2 small iterations
after the first real run. The user supervises closely.

---

## 一句话目标

当 `llm_client` 可用时，`pipeline.py` 在 `build_digest` 之后、`render_digest` 之前，
为每个 `DigestSection` 调一次 `generate_section`，把结果挂到 `DigestSection.llm_brief`；
模板根据 `llm_brief` 是否为 `None` 选择中文简报或老路径。

## 已有基础

- `src/ecobio_daily/llm_digest.py`：`generate_section(topic, items, client) -> dict | None`
- `src/ecobio_daily/llm.py`：`LLMClient` + cache
- `src/ecobio_daily/digest.py`：`build_digest` 已返回 `Digest(sections=[DigestSection(...)])`
- `src/ecobio_daily/pipeline.py`：已经接受 `llm_client` 参数（G2 引入）
- `src/ecobio_daily/render.py`：用 jinja2 渲染 `templates/digest_zh.md.j2`
- 缓存生效：迭代 prompt 时改 `.j2` 自然让缓存失效

## 范围

**DO:**

- `src/ecobio_daily/models.py`：`DigestSection` 加 `llm_brief: dict | None = None`
- `src/ecobio_daily/pipeline.py`：
  - 在 `build_digest` 之后，如果 `llm_client is not None`，遍历每个 `section`，
    调 `generate_section(section.title, section.items, llm_client)`，结果（含 `None`）
    赋给 `section.llm_brief`
  - 单个 section 失败（`None`）不影响其他 section
  - 输出 stderr 简短提示：成功 N 个 / 失败 M 个
- `templates/digest_zh.md.j2`（**先读现有结构再动手**）：
  - 每个 section 渲染时，**如果 `section.llm_brief` 不为 None**：
    - 用 `llm_brief.section_title` 作为标题（如果存在）否则用 `section.title`
    - 输出 `llm_brief.highlights` 作为这个 section 的 3 条要点（项目级 Highlights 仍按旧逻辑取顶部）
    - 每个 item 用 `llm_brief.items[i]` 的 `summary_zh` / `why_it_matters` / `evidence_type` / `caveat`
  - **否则**：走老的英文 RSS 摘要拼接路径
- 测试：
  - `tests/test_pipeline.py` 加一个 monkeypatch `generate_section` 的测试：
    - 模拟某 section 返回 dict，另一个返回 None
    - 验证 `Digest.sections[i].llm_brief` 形态正确
  - `tests/test_render.py`（如果存在；否则新建一个最小测试）：
    - 一个 section 有 `llm_brief` → 输出包含 `summary_zh` 内容
    - 一个 section 没有 `llm_brief` → 输出包含原 `item.summary`

**DON'T:**

- 不调 deepseek-v3.2 的 `temperature` / `max_tokens`（先用默认）
- 不改主题配置 `config/topics.yaml`
- prompt 改了写在 `templates/prompts/digest_section_zh_*.md.j2`，不要在 `.py` 里硬塞
- 不重构 `build_digest` / `render_digest` 的核心逻辑——只插入新数据通路

## Prompt 微调清单（如果需要）

| 症状 | 微调点 |
|---|---|
| `summary_zh` 过长 / 逐句翻译 | 在 system prompt 加"≤ 60 字、必须重组不可逐句翻译" |
| `evidence_type` 总是猜"实验" | 加例子："综述 = review / meta-analysis；模型 = simulation / climate model"|
| `highlights` 重复 `summary_zh` 内容 | 加"highlights 必须是跨多篇论文的概括，不要复述单篇" |
| `caveat` 总是 null | 加"caveat 必须存在，且不能空泛说'需要进一步研究'" |
